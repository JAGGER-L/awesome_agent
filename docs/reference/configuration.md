# Configuration reference

Awesome uses two schema-validated YAML documents, a small set of process
environment variables, and Thread-scoped choices stored in Application state.
These sources serve different trust boundaries; they are not interchangeable.

| Source | Location | Owner | When read | May contain secrets |
| --- | --- | --- | --- | --- |
| User configuration | `<AWESOME_HOME>/config.yaml` | Local user | Startup and supported configuration changes | No |
| Awesome credential file | `<AWESOME_HOME>/.env` | Local user | Startup and `/auth` changes | Yes |
| Process environment | Parent process | Launcher/user | Startup | Yes |
| Workspace configuration | `<workspace>/.awesome/config.yaml` | Repository | Only after workspace trust | No |
| Thread state | `application.db` | Awesome | Thread selection and each Turn | No |

User configuration uses schema version `2`; workspace configuration remains at
version `1`. A user version-1 document is upgraded only in memory while it is
read, then written atomically as version 2 by the first supported configuration
change. Unknown fields, duplicate mapping keys, values with the wrong native
YAML scalar type, and out-of-range values
invalidate the whole document. Validation does not coerce quoted numbers or
booleans: use `32`, not `"32"`, and `false`, not `"false"`. Enum values remain
their documented strings, YAML sequences remain the representation for lists,
and `null` is accepted only for fields that explicitly permit it.

## User configuration

The following is a complete valid document. Every field shown with its default
can be omitted.

```yaml
version: 2

providers:
  default_model: deepseek/deepseek-v4-flash
  kimi_region: cn

credentials:
  deepseek: environment
  kimi: awesome
  mem0: awesome
  tavily: environment
  web_proxy: null

budgets:
  model_calls: 32
  tool_calls: 64
  provider_retries: 2
  compressions: 2
  active_execution_seconds: 1800
  total_context_tokens: 262144
  web_requests: 8

web:
  enabled: false
  provider: tavily
  blocked_domains: []

memory:
  local_file_memory: false
  mem0_cloud: false
  # Normally generated by Awesome when Mem0 is enabled.
  mem0_user_id: user_0123456789abcdef0123456789abcdef

skills:
  disabled:
    - legacy-review

mcp_servers:
  - id: issue-tracker
    command: npx
    args:
      - -y
      - '@example/issue-tracker-mcp@1.0.0'
    env:
      - ISSUE_TRACKER_TOKEN
    enabled: false
```

### `providers`

| Field | Type and values | Default | Meaning |
| --- | --- | --- | --- |
| `default_model` | Curated model ID or `null` | `null` | Initial model for a new Thread when no startup model is supplied. |
| `kimi_region` | `cn` or `global` | `cn` | Kimi API region used by the Provider adapter. |

The curated model IDs are:

- `deepseek/deepseek-v4-flash`
- `deepseek/deepseek-v4-pro`
- `kimi/kimi-k2.6`
- `kimi/kimi-k2.5`

All four current profiles advertise a 262,144-token context window plus tool
calling and reasoning. Curating the list lets the Core bind known capabilities
and context limits instead of trusting an arbitrary model string. `/model`
updates both the selected Thread and this user default.

If no default is set, Awesome selects the sole configured Provider's default
model. If zero or multiple Providers are configured, a model must be chosen
before an Agent Turn can start.

### `credentials`

The static credential catalog defines five services:

| Service | Environment variable | `awesome` storage |
| --- | --- | --- |
| DeepSeek | `DEEPSEEK_API_KEY` | `DEEPSEEK_API_KEY` in `<AWESOME_HOME>/.env` |
| Kimi | `MOONSHOT_API_KEY` | `MOONSHOT_API_KEY` in `<AWESOME_HOME>/.env` |
| Mem0 | `MEM0_API_KEY` | `MEM0_API_KEY` in `<AWESOME_HOME>/.env` |
| Tavily | `TAVILY_API_KEY` | Not supported; this selection must be `environment` |
| Web proxy | `AWESOME_WEB_PROXY_URL` | `AWESOME_WEB_PROXY_URL` in `<AWESOME_HOME>/.env` |

DeepSeek, Kimi, Mem0, and Web proxy accept `environment`, `awesome`, or an
omitted/`null` selection. With no explicit selection, a non-empty process environment value wins; the
Awesome credential file is used only when the environment value is absent. An
explicit source never falls back to the other source. For example, selecting
`environment` while the variable is missing reports that Provider as not
configured even if `<AWESOME_HOME>/.env` contains a key. This makes provenance
visible and prevents an operator from unknowingly using stale local secrets.

Do not put keys in YAML or workspace files. `/auth` writes the Awesome credential
file atomically, masks secret input, and never exposes its value through
`/config` or protocol state. DeepSeek and Kimi keys are remotely validated
before normal saving (with an explicit save-unverified path for reachability
failure). Mem0 keys receive only local format/storage validation and are saved
without a remote check; rejection appears when the cloud adapter is enabled or
called. `/auth` currently manages DeepSeek, Kimi, and Mem0; it does not edit the
Tavily or Web proxy entries. See [files and state](files-and-state.md) for
ownership and backup guidance.

### `budgets`

| Field | Default | Valid range | Boundary controlled |
| --- | ---: | ---: | --- |
| `model_calls` | 32 | 1–256 | Provider calls in one Turn, including compression/distillation calls where applicable |
| `tool_calls` | 64 | 1–512 | Tool calls in one Turn |
| `provider_retries` | 2 | 0–6 | Retries after the first Provider attempt |
| `compressions` | 2 | 0–10 | Context compression passes in one Turn |
| `active_execution_seconds` | 1,800 | 1–21,600 | Active foreground execution time for one Turn |
| `total_context_tokens` | 262,144 | any positive integer | Requested total context budget before the model profile and input allocation reduce it |
| `web_requests` | 8 | 0–8 | Maximum Web requests reserved for one Turn; a workspace may only lower it |

A budget is a circuit breaker, not a target. A Turn may finish far below it.
`total_context_tokens` is capped again by the selected model profile; the Context
Builder reserves output/headroom before allocating effective input. Provider
retries do not make non-idempotent tools repeat.

### `web`

| Field | Type and values | Default | Meaning |
| --- | --- | --- | --- |
| `enabled` | boolean | `false` | User-owned Web enablement. Workspace configuration cannot turn it on. |
| `provider` | `tavily` | `tavily` | Static Web Provider selection, separate from model Providers. |
| `blocked_domains` | up to 128 unique normalized ASCII hostnames | `[]` | Additional destinations rejected before a Web request. |

This configuration increment establishes the closed contract and credential
catalog; by itself it does not register a Web tool or grant network authority.

### `memory`

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `local_file_memory` | boolean | `false` | Load bounded user/workspace Memory and register local Memory tools. |
| `mem0_cloud` | boolean | `false` | Enable scoped cloud recall and post-answer distillation. |
| `mem0_user_id` | `user_` plus 32 lowercase hexadecimal characters, or `null` | `null` | Opaque local identity used to scope Mem0 records. |

Awesome normally creates `mem0_user_id` when cloud Memory is first enabled. It
is deliberately opaque: an email address or repository path would expose more
identity than recall needs. Full behavior and policy are in
[Memory](../extensions/memory.md).

### `skills`

`skills.disabled` is a unique list of names matching
`[a-z][a-z0-9_-]{0,63}`. A disabled name applies across Workspace, User, and
Bundled sources. If both user and workspace documents disable Skills, the
effective set is their union. See [Skills](../extensions/skills.md).

There is a current grammar mismatch: configuration accepts `_`, but discoverable
and selectable Skill names allow only lowercase letters, digits, and `-`. A
disabled entry containing `_` is therefore valid configuration that cannot
match any actual Skill. Use hyphenated names; aligning these validators is a
runtime contract-hardening task.

### `mcp_servers`

| Field | Required | Constraints | Meaning |
| --- | --- | --- | --- |
| `id` | yes | `[a-z][a-z0-9_-]{0,63}`; unique across the effective catalog | Registry namespace in `mcp.<id>.<tool>`. |
| `command` | yes | 1–2,000 characters | Executable launched directly, without an intervening shell. |
| `args` | no | list of strings | Exact argument vector. |
| `env` | no | unique uppercase names matching `[A-Z_][A-Z0-9_]*` | Parent environment names permitted into the server process. |
| `enabled` | no | boolean, default `false` | User-server startup enablement. |

User MCP declarations are locally owned, so their `enabled` bit lives in user
YAML. Workspace declarations use a separate config-hash-bound approval and do
not have this field. See [MCP](../extensions/mcp.md).

## Workspace configuration

A workspace can only make budgets stricter, disable Skills, and declare MCP
servers. It cannot choose credentials, enable Memory, choose a model, or raise a
user safety limit.

```yaml
version: 1

budgets:
  model_calls: 20
  tool_calls: 40
  provider_retries: 1
  compressions: 1
  active_execution_seconds: 900
  total_context_tokens: 131072
  web_requests: 3

skills:
  disabled:
    - deployment

mcp_servers:
  - id: repository-index
    command: repository-index-mcp
    args:
      - --stdio
    env:
      - REPOSITORY_INDEX_TOKEN
```

Every workspace budget field is optional and has the same range as its user
counterpart. The effective value is `min(user value, workspace value)` for each
field independently. That monotonic rule is the key design invariant: content
from a trusted repository may reduce resource authority, but never enlarge the
local user's authority.

The file is not opened until the user trusts the workspace. Its read is capped
at 1 MiB, requires strict UTF-8 text without NUL, pins and rechecks the workspace
and path identities, and rejects links, reparse points, hard links, and
replacement during the read. An unsafe or oversized file invalidates workspace
configuration rather than being followed or truncated. Trust does not turn MCP
declarations on; each workspace server still requires `/mcp enable <id>`, and
changing its declaration invalidates that approval.

## Runtime precedence

Configuration resolution is field-specific rather than one document simply
overwriting another:

```text
User YAML --------------------------> Application configuration
Trusted workspace YAML ------------> Application configuration
  (minimum budgets, disabled union,             |
   and MCP declarations)                        |
                                                v
Persisted Thread choices -----------------> Turn configuration
AWESOME_MODEL at new-Thread creation ------>    |
                                                v
                              model + Thinking + Skill mode
                                    + effective budgets

Process credentials ----+
                        +----------> selected credential source
Awesome .env ------------+
```

For a new Thread, model selection is: `AWESOME_MODEL`, then
`providers.default_model`, then the sole configured Provider's default. The
selected value is persisted on the Thread. Existing Threads use their persisted
model; `/model`, `/thinking`, and `/skills` update future Turns on that Thread.

The low-level Turn resolver also has `AWESOME_THINKING` and `AWESOME_SKILL`
branches for isolated callers and tests. The shipped CLI exposes no startup
flags for them, and the current Application composition intentionally resolves
actual Turns with an empty override environment. Therefore
`AWESOME_THINKING` and `AWESOME_SKILL` are **not public launcher controls** in
this release; use `/thinking` and `/skills`. Documenting this distinction keeps
an internal resolver seam from becoming an accidental compatibility promise.

## Process environment and path overrides

| Variable | Effect |
| --- | --- |
| `AWESOME_HOME` | Overrides the complete user data root. |
| `AWESOME_MODEL` | Sets the initial model of Threads created in this process; must be a curated ID. |
| `DEEPSEEK_API_KEY` | DeepSeek credential when its selected source is `environment`. |
| `MOONSHOT_API_KEY` | Kimi credential when its selected source is `environment`. |
| `MEM0_API_KEY` | Mem0 credential when its selected source is `environment`. |
| `TAVILY_API_KEY` | Tavily credential; its source is always `environment`. |
| `AWESOME_WEB_PROXY_URL` | Explicit Web proxy when `credentials.web_proxy` resolves to `environment`. |

`AWESOME_HOME` accepts a platform path and expands the home marker supported by
the host runtime. An empty value behaves as unset. Changing it selects a
different state/config universe; it is not a safe way to move only one
database.

`AwesomePaths.resolve()` also reads `AWESOME_INSTALL_DIR` into its low-level
`install_dir` field, but current production code does not consume that field.
The official installers and generated launchers use their fixed platform
installation roots and do not read this variable. It is therefore not a
supported application relocation control.

MCP `env` entries copy only variables already present in the Core process
environment. Values stored in Awesome's credential file are Provider secrets,
not a general-purpose environment loader, and are not automatically exported
to MCP servers.

## Diagnosing configuration

Use `/config` to inspect source paths, selected credential sources, and presence
flags without revealing secret values. Use `/doctor` when a Provider check is
appropriate. Common failures are:

| Symptom | Cause | Corrective action |
| --- | --- | --- |
| `duplicate_config_key` | A YAML mapping repeats a field. | Remove the duplicate; do not rely on last-key-wins behavior. |
| `configuration_invalid` | Unknown field, invalid enum/model/name, non-native scalar type, out-of-range budget, or unsafe/oversized workspace config. | Compare the document with the tables above and keep `.awesome/config.yaml` a plain UTF-8 file no larger than 1 MiB. |
| `provider_not_configured` | The selected model's explicitly selected credential source is unavailable. | Use `/auth`, set the selected environment variable, or change `credentials`. |
| `model_not_configured` | No model can be selected unambiguously. | Use `/model` or set `providers.default_model`. |
| workspace settings appear ignored | Workspace has not been trusted, or the file is not at `.awesome/config.yaml`. | Complete the trust interaction and restart. |

Configuration is a startup snapshot except for changes made through supported
commands, which update the active Application state deliberately. Editing YAML
behind a running process is not a hot-reload contract; restart Awesome after a
manual edit.
