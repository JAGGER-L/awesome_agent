# 上下文与指令

本页说明模型能够看到什么、为什么不能永远原样发送完整 transcript，以及项目指令与 Memory、Skills 有何不同。需要获取某个 Turn 的证据时，请使用 `/context`。

## 上下文是一项构建产物

模型接收的是由 Core 组装的有界序列。模型不能隐式读取终端、数据库或 Workspace。

```text
产品身份/指令 ------------------+
根 AGENTS.md 快照 --------------+
选中的 Skill ------------------+
Memory -------------------------+--> 排序、去重、预算 --> 模型
Thread 摘要 + 近期历史 ---------+
direct-command 历史 ------------+
显式 @path ---------------------+
当前请求 + 开放的工具链 --------+
```

每个保留的来源都会成为 context manifest 项，其中包含类型、source ID、顺序、估算 Token 数、内容 hash 和截断状态。`/context` 会展示最近有意义的 manifest 和预算，且不会暴露凭据。

## 权限不由文件格式决定

多个输入都采用 Markdown，但它们的权限并不相同：

- 产品指令是强制 system policy；
- 已接受的根 `AGENTS.md` 是强制 Workspace 指令；
- 活动 Skill 为该 Turn 提供强制工作流指令；
- Memory 被明确包装为不受信的参考数据；
- 会话历史、direct-command 结果和显式路径提供证据与任务上下文；
- 当前用户请求说明眼前目标。

Memory 中即使含有祈使语句，也不能越过工具策略。同理，Skill 可以指导使用哪些工具，但不能绕过 registry、权限决策、路径策略或命令 circuit breaker。

## 根 `AGENTS.md` 是 Session 快照

完成信任后，Core 只查找 Workspace 根目录下恰好一个普通 `AGENTS.md`。它以有界、身份检查的方式读取文件，并为当前 Session 冻结结果。只有内容稳定、采用 UTF-8、没有 NUL 字节，且不存在链接、junction、reparse 组件或路径逃逸时，文件才会被接受。

字节上限为 32 KiB。Token 配额是 8,192 Tokens 和有效输入预算 10% 中的较小值。超过任一限制都会拒绝整个文件。Awesome 不保留任意前缀，因为截断“仅在 Y 时执行 X”可能反转项目策略的含义。

即使相同文字出现在产品或 Skill 内容中，已接受的 Workspace 指令仍会作为独立 manifest 来源保留。没有指令文件是正常情况。文件被拒绝时，Welcome、状态栏和 `/doctor` 会显示结构化警告；修复文件并启动新 Session 才能取得新快照。

根指令示例：

```markdown
# 项目指令

- 先运行聚焦的 package test，再运行完整测试套件。
- 不要编辑 `dist/` 下的生成文件。
- 保持公共 API 向后兼容，除非任务明确要求更改它。
```

指令应稳定、针对当前仓库且可验证。请把临时任务细节放在请求中，而不是反复编辑 `AGENTS.md`。

## 显式路径

`@path` 引用要求 Core 把特定 Workspace 文件或目录引用加入当前请求。当大型仓库存在多个可能的入口时，这很有用：

```text
审查 @src/payments/settlement.py 及其测试的重试安全性。
```

路径引用使用与内置工具相同的有界、不跟随链接的 Workspace 读取方式。它不会授予 Workspace 外部访问权限，也不会使路径变为可编辑。应优先选择范围较窄的文件或目录，而不是 `@.`，避免相关证据因空间不足而挤掉其他上下文。

## 预算与排序

Core 首先取配置的上下文总量与所选模型实际上下文上限中的较小值。它会预留输出容量和安全余量；剩余部分就是有效输入上限。强制来源必须全部放入该上限，否则 Turn 会失败，而不会悄悄丢弃策略。

可选来源按确定顺序排列并使用剩余预算。同一信任类别内的重复可选内容会被去除；即使文本重复，时间线条目仍会保持顺序。长期 Memory 有自己的有界份额，因此不断增长的 Memory 存储不会挤掉当前请求。

精确默认值和限制见[配置参考](../reference/configuration.zh-CN.md)。

## 压缩

当上下文接近阈值时，Awesome 可以对较早且已完成的 Turn 进行总结，同时完整保留近期 Turn。总结 prompt 要求模型保留目标、决策、变更文件、验证、失败、direct-command 结果和未解决工作。结果会连同其覆盖的序列一起存储，并显示在 manifest 中；已总结 Turn 的精确措辞和细节仍可能丢失。

```text
较早的已完成 Turn --模型总结--> 持久 Thread 摘要
最近四个已完成 Turn ----------------------> 原样保留
当前/开放工作 ----------------------------> 原样保留
```

运行 `/compact` 可显式请求压缩。如果没有足够的已完成历史可供总结，可能不会发生任何变化。自动压缩同样会消耗配置的模型/重试/压缩预算。如果压缩失败但当前上下文仍能放入预算，Turn 可以继续使用现有上下文；如果强制内容本身超过上限，则无法继续。

压缩以旧内容的精确措辞换取持续的连贯性。如果精确的历史表述比无限延续长会话更重要，请开始新的 Thread。

## 检查与诊断

使用：

```text
/context
/usage
/compact
/doctor
```

`/context` 回答组装了什么；`/usage` 回答 Thread 已消耗什么；`/compact` 更改 Thread 摘要；`/doctor` 解释 Workspace 指令文件为什么被拒绝。如果模型看起来忽略了某个文件，请确认它是否出现在 context manifest 中，或使用 `@path` 显式引用。

扩展特有的上下文请阅读 [Memory](../extensions/memory.zh-CN.md) 和 [Skills](../extensions/skills.zh-CN.md)。实现所有权见[架构指南](../architecture/README.zh-CN.md)。
